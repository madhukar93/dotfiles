# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

This is a [chezmoi](https://www.chezmoi.io/)-managed dotfiles repository. It is the chezmoi *source directory*
(`~/.local/share/chezmoi`), not the files that actually get used at runtime — those live in `$HOME` and are
generated from this repo by chezmoi. Note that this repo is distinct from `~/.config/chezmoi/`, which only
holds chezmoi's own tool config (`chezmoi.toml`) and state database, not the dotfiles themselves.

chezmoi maps source paths to target paths via prefix stripping, e.g.:
- `dot_zshrc` → `~/.zshrc`
- `dot_config/nvim/init.lua` → `~/.config/nvim/init.lua`
- `dot_config/private_karabiner/private_karabiner.json` → `~/.config/karabiner/karabiner.json` (`private_` marks a directory chezmoi creates with restricted permissions)

There is no build, lint, or test tooling in this repo — it's pure configuration. There are no chezmoi templates
(`.tmpl` files), no `.chezmoiroot`, and no scripts under `.chezmoiscripts`, so files map 1:1 from source to
target without templating logic to reason about.

## Common chezmoi commands

```sh
chezmoi diff              # preview what `apply` would change in $HOME
chezmoi status             # short status: source vs target vs actual state (X Y path)
chezmoi apply               # write source state out to $HOME
chezmoi add ~/.zshrc         # pull a live dotfile's current content back into the source dir
chezmoi cd                   # cd into this source directory in a subshell
chezmoi doctor                # diagnose chezmoi environment/config issues
```

Because there's no templating, `chezmoi diff`/`status` differences are always genuine content drift between
the committed source and the live file in `$HOME` — not template evaluation differences. Before assuming the
source of truth is up to date, check `chezmoi status`: it's common for live edits (e.g. quick tweaks to
`~/.wezterm.lua` or `~/.tmux.conf.local`) to exist locally before being `add`ed back into this repo and
committed.

## Layout and what each piece configures

- **`dot_zshrc`, `dot_zshenv`** — zsh, using oh-my-zsh (`ZSH_THEME="robbyrussell"`), vi keybindings
  (`bindkey -v`), and a large set of tool-specific PATH/env exports and aliases (kubectl, terraform, gcloud,
  nvm, rbenv/sdkman, Android SDK, Homebrew paths). The SDKMAN block **must stay at the end of the file** —
  sdkman's own installer requires this.
- **`dot_config/fish/`** — fish shell config (`config.fish`) plus a Fisher plugin list (`fish_plugins`).
  Fish is the interactive shell actually launched by terminals (see `dot_wezterm.lua`'s `default_prog`); zsh
  config still exists and is kept in sync loosely but fish is primary day-to-day.
- **`dot_wezterm.lua`** — WezTerm terminal config. Uses `wezterm.plugin.require(...)` to pull in
  `mrjones2014/smart-splits.nvim` (pane nav shared with Neovim/tmux) and `madhukar93/bar.wezterm` (a status
  bar plugin, also authored by this user). Leader key is `Ctrl-a`. Defines an `ssh`-proxied unix domain
  (`madhukar-pc-tailscale`) for connecting to a remote machine over Tailscale.
- **`dot_tmux/dot_tmux.conf`** — the upstream `gpakosz/.tmux` framework config. **Do not edit this file
  directly** (it says so in its own header) — all customization belongs in `dot_tmux.conf.local`.
- **`dot_tmux.conf.local`** — the actual tmux customization: theme colors, plugin list (via manually-vendored
  `tmux-plugins/tpm`-style `set -g @plugin` lines — note the repo does **not** use tpm's bootstrap, per the
  `/!\ do not add run '~/.tmux/plugins/tpm/tpm'` comment), and Neovim-aware pane navigation bindings
  (`C-h/j/k/l` check `#{@pane-is-vim}` before falling back to `select-pane`) that mirror the same scheme used
  in wezterm and Neovim's `smart-splits.nvim` plugin — the three are meant to compose into one consistent
  navigation model across terminal multiplexer, terminal emulator, and editor.
- **`dot_config/nvim/`** — Neovim config built on [LazyVim](https://lazyvim.github.io) (a starter/distro, not
  built from scratch). `init.lua` just requires `config.lazy`, which bootstraps `lazy.nvim` and loads
  `lazyvim.plugins` plus this repo's own `lua/plugins/*.lua` specs.
  - `lua/config/{options,keymaps,autocmds}.lua` — loaded automatically by LazyVim at the documented points;
    additions go here, not by editing LazyVim internals.
  - `lua/plugins/*.lua` — each file returns a lazy.nvim plugin spec (or list of specs); this is the idiomatic
    LazyVim way to add plugins or override `opts` on existing ones (see the file-level comments in
    `lua/plugins/example.lua`, which is a reference/scratch file whose top line disables it —
    `if true then return {} end` — so it loads no plugins itself).
  - `lazy-lock.json` is the plugin version lockfile; `lazyvim.json` tracks which optional LazyVim "extras"
    (language/editor bundles) are enabled. Both are regenerated by Neovim/Lazy itself — don't hand-edit,
    `chezmoi add` them after they change.
  - `dot_gitignore`, `dot_neoconf.json` map to `.gitignore`/`.neoconf.json` inside `~/.config/nvim/`.
  - `nvim.bak/` is a legacy vim-plug + coc.nvim config kept for reference; it is not loaded by the active
    `init.lua`.
- **`dot_config/starship.toml`** — prompt config (starship), shared across shells; includes a custom
  `[kubernetes]` context-pattern → color mapping (e.g. GKE/EKS contexts shown in red as a visual "prod"
  warning, local/orbstack contexts in green).
- **`dot_config/zed/private_settings.json`** — Zed editor settings (vim mode enabled).
- **`dot_config/pgcli/config`** — pgcli (Postgres CLI) config.
- **`dot_config/private_karabiner/private_karabiner.json`** — Karabiner-Elements keyboard remapping (notably
  caps_lock ↔ control/escape dual-role).

## Working in this repo

- Treat `dot_tmux/dot_tmux.conf` as vendored/upstream — changes belong in `dot_tmux.conf.local` instead.
- Cross-tool consistency matters here: pane-navigation keybindings (`C-h/j/k/l`) are intentionally mirrored
  across `dot_tmux.conf.local`, `dot_wezterm.lua`, and the nvim `smart-splits.nvim` plugin spec. If you change
  one, check whether the others need the same change to keep the "seamless navigation" behavior working.
- After hand-editing a live file in `$HOME` (as opposed to editing here), remember to `chezmoi add` it back
  into this source tree, or the change will be lost / overwritten on the next `chezmoi apply`.
